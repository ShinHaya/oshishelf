# 審査用デモの操作手順と確認記録

## 動作確認の方法

対象URLは https://oshi-dana.com です。
ログイン画面で「デモアカウントでログイン」を押してください。
共有の審査用アカウントへログインするため、Googleアカウントの選択やメールの受信は不要です。
認証情報をフォームに記載する場合は、提出資料にある審査用情報を「審査向け情報」にのみ転記してください。

サンプルユーザー「デモ太郎」「みか」「けんじ」「てつ」「ゆき」の棚で操作できます。
実際の購入履歴、個人情報、成人向け作品は共有アカウントへ入力しないでください。
既存の作品やプロフィールを削除せず、確認してから操作してください。

| 操作 | 手順と期待する結果 |
| --- | --- |
| 棚と購入リンク | 「自分の棚」でマンガ、書籍、ゲームを表示します。「ショップで見る」「ショップで探す」から外部サイトへ移動できます。購入自体は不要です。 |
| 取り込みと本人確認 | 「取り込む」で、架空の購入履歴テキストまたは一般向け商品URLを入力します。結果は下書きになります。「確認して公開」で要確認商品の選択が外れていることを確認し、公開してよいサンプルだけ選びます。 |
| AI自己紹介 | 「設定」の「自己紹介を生成する」（生成済みなら「もう一度生成する」）を押します。下書きと行動ログを確認してから「この内容でプロフィールに公開」を押します。生成しただけでは公開されません。 |
| 相性分析 | 「見つける」からサンプルユーザー「みか」の棚を開きます。「相性を分析する」で共通点、おすすめ、話しかけ例を表示します。生成済みなら「再分析」で新しい分析を実行できます。 |
| AI分身 | 「みか」の棚の「AI分身と話す」で「初心者におすすめの1冊を教えて」を選びます。回答中の作品リンクから商品ページへ移動できます。 |
| ウォッチャー | 「ほしい」で商品ページのリンクを持つ作品を確認し、「通知」の「今すぐ巡回する」を押します。確認した価格、通知件数、行動ログが表示されます。値下がりがなければ値下がり通知は出ません。 |
| 終了 | 「ログアウト」を押します。棚の編集や設定を開くとログイン画面へ戻ります。 |

全体の所要時間はAIの待ち時間を含め5〜10分程度を目安にしてください。
これは操作手順の目安で、応答時間の保証ではありません。
動画は待ち時間をカットして約3分に編集できます。

## 利用上限と繰り返し操作

共有アカウントのAI利用回数は利用者全員で共有します。
現在のコードでは日付をUTCで区切るため、日本時間の午前9時に次の日の枠へ切り替わります。

| 機能 | 1日あたりの上限 |
| --- | ---: |
| テキスト、URL、ブックマークレットによる取り込み | 合計40回 |
| スクリーンショット | 15枚分 |
| AI自己紹介 | 10回 |
| 相性分析 | 30回 |
| AI分身チャット | 60回 |
| 手動ウォッチャー | 5回 |

取り込み候補は1日300件（Authアカウント作成から7日未満は50件）、サービス全体では3,000件です。
Geminiの商品情報フォールバックは1回最大5件、1日10件、サービス全体で100件です。
これらはmainのコード上の制御で、本番反映は今回未確認です。
詳細は[開発ガイド](development.md#ai利用量の上限)を参照してください。

同じ商品は重複を検出してスキップします。
撮り直しで既存サンプルを削除する代わりに、別の架空サンプルを用意してください。
相性分析は生成から24時間以内のキャッシュを再利用し、「再分析」で再生成します。
相性キャッシュの既存Issue #12はPR #38で修正し、mainへマージ済みです。
本番反映は未確認のため、公開範囲変更後の本番表示が安全になったとは扱わないでください。
[安全性と費用の評価](safety-cost-assessment.md)と、以下の修正実装の記録を参照してください。
価格が商品ページから取得できない作品や検索結果リンクは、価格監視の実演に向きません。

## 安全性Issueの修正実装（2026年10月14日）

#9、#10、#12、#14、#15の修正は[PR #38](https://github.com/ShinHaya/oshishelf/pull/38)でmainへマージ済みです。
この記録はコードとローカル検査の結果であり、前掲の本番確認記録を更新するものではありません。
本番反映と、独立した開発用クラウドでの認証、保存、複数アカウントによる通し確認は未実施です。

| Issue | 修正後の挙動 | 検証対象 |
| --- | --- | --- |
| #9、#10 | 商品URLはHTTP(S)かつ認証情報なしに限定。正規ドメインとサブドメインだけをショップと判定する。未知ショップの購入リンクは、実際のURLを表示する確認画面から進む。 | 保存境界、取り込み前の拒否、偽ドメイン、アフィリエイト、保存済み危険URL、公開範囲、所有者の成人向け閲覧例外。 |
| #12 | 相性結果は24時間以内でも、両者の現在の公開棚と同意設定が生成時と一致した場合だけ表示する。古い形式のキャッシュは使わない。生成中に棚や同意が変わった場合も結果を返さない。 | 両者の非公開化、フォロワー限定化、下書き化、削除、成人向け同意、TTL境界、生成中と保存中の変更、モデルの架空ID除外、成人向けAI入力の伏せ字。 |

| #15 | ログアウトでFirebaseの同アカウントのセッションを失効させる。POSTとDELETEは同一originを要求する。内部エラーはサーバーログに残し、画面には汎用メッセージを返す。 | 失効呼び出し、別originと異なるスキームやポートの拒否、無効Cookie、失効失敗、利用上限メッセージの維持、内部エラーとスキーマ詳細の非表示。 |

修正後のログアウトは、同じアカウントの別ブラウザにも再ログインを要求します。
共有デモアカウントの利用者同士も影響を受けます。
Firebaseが失効処理に失敗した場合はログアウト完了として画面遷移せず、再試行を表示します。

相性キャッシュの照合には現在の棚を読むため、キャッシュ利用時にもFirestoreの読み取りが発生します。
キャッシュが存在しない場合と期限切れの場合は、照合のための棚読み取りを省きます。
公開棚の変更で無効になった結果の再生成は、従来どおりAI利用上限を消費します。
以前取得した画面やスクリーンショットから情報を回収する機能はありません。

共有アカウントの下書きと「自分のみ」は、同アカウントの他の利用者からも見えます。
実購入履歴や個人情報は入力せず、成人向けの表示同意とAI利用同意は変更しないでください。
所有者権限と同意設定が共有される性質は、この修正でも維持されます。

### 本番反映前後の確認手順

- 開発用の架空アカウント2件で相性を生成し、片側の作品の非公開化、フォロワー限定化、削除後に再読み込みして分析全体が消えることを確認する。成人向け同意変更でも確認する。
- 正規ショップ、未知ショップ、偽ドメインの架空作品で購入リンクを開き、未知ショップだけが確認画面を挟むことを確認する。非所有者からの下書きと非公開作品のリンクは404になることを確認する。
- 購入履歴ページのブックマークレットから、実送信元とリンク一覧が表示されることを確認する。別originをページoriginとして名乗ったペイロードは取り込めないことを確認する。
- 開発用アカウントでログアウトし、別ブラウザの既存セッションも拒否されることを確認する。共有デモのログアウトによる他の利用者への影響を案内する。
- 別途承認された本番反映後にデモ導線と資料を照合する。保存済み相性キャッシュは旧形式が無効になるため、公開デモの表示に必要な場合は利用上限内で再分析する。

これらの実クラウドと本番の確認は未完了です。
seed、インデックス変更、データ削除を通常の検証として実行しません。

### 修正実装のローカル確認結果

Node.js 22.23.1で `pnpm check`（18ファイル、266テスト）と `pnpm build` が成功しました。
追加した主要回帰テストをmainの修正前コードに対して実行すると、購入リンク、相性キャッシュ、受信元、セッション失効、内部エラーの8件が失敗しました。
その後実装を戻し、全テストの成功を確認しました。

ローカルの本番ビルドをCookieなしでHTTP確認しました。
ログイン画面は200で、CSPの `frame-ancestors 'none'`、X-Frame-Options、HSTS、X-Content-Type-Options、Referrer-Policyを確認しました。
別originのDELETEは403、同一originでCookieなしのDELETEは200、不正なPOST本文は400でした。
本番プロジェクトを使わず、FirebaseとFirestoreへの操作は行っていません。
これは実際のログインや失効の確認には含めません。
