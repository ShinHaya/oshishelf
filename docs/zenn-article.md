## 一言でいうと

**推し棚（OshiShelf）** は、FANZA・DLsite・Amazon・Steam など、どこで買った作品でも「棚」に並べて公開し、同じ趣味のファン同士がつながれるSNSです。
フォローした人の棚で気になった作品は、そのまま商品ページに飛んで買えます。

そして、この棚づくりと人とのつながりを **6つのAIエージェント** が支えます。
購入履歴の取り込み、公開前のプライバシーチェック、自己紹介文の作成、趣味の合う人探し、本人の「分身」との会話、値下がりと新作の自動巡回です。

## 解決したい課題

### 「何を買ったか」は、その人の趣味をいちばん正直に表すのに、見せ合う場所がない

マンガ、同人誌、インディーゲーム、映像作品。ファンにとって「何を買ったか」は、SNSの自己紹介文よりずっと雄弁なプロフィールです。
ところが購入履歴はショップごとに閉じていて、ファン同士で見せ合う手段がありません。

### 手で棚を作るのは面倒で、しかも「見られたくない物」が混ざる

読書記録サービスのように手入力で棚を作る方法はあります。でも、何十冊・何百本もの購入履歴を手で登録するのは現実的ではありません。
さらに購入履歴には、健康に関わる商品、贈り物、仕事で使う専門書、成人向け作品など、**人に見られたくない物が自然に混ざります**。
「全部まとめて公開」は危険で、「1件ずつ確認」は面倒。これが購入履歴を公開できない本当の理由だと考えました。

### 趣味の合う人を見つけても、最初の一言が難しい

同じ作品を好きな人を見つけても、いきなり話しかけるのはハードルが高いものです。

## 推し棚の体験

1. **購入履歴を一括で取り込む**: ショップの購入履歴ページでブックマークレットを押すだけ。スクリーンショットや商品URLからでも取り込めます。
2. **AIが「見られたくないかも」を先に見つける**: 取り込んだ商品はすべて下書きになり、プライバシーガードが要確認の物を選び出します。公開するかどうかは本人が決めます。
3. **棚から自己紹介ができる**: AIが棚を調べて趣味嗜好を推論し、自己紹介文を下書きします。
4. **趣味の合う人とつながる**: 嗜好ベクトルが近い人をAIが推薦し、相性の理由・おすすめ作品・話しかけ方まで提案します。
5. **気になる作品はすぐ買える**: フォローした人の棚から、ワンクリックで商品ページへ。
6. **ほしい物はAIが見張る**: ♡を付けた作品の値下がりや、好きなジャンルの新作を毎朝自動で巡回して通知します。

## 6つのAIエージェント

| エージェント | 何をするか | 主な技術 |
|---|---|---|
| 📥 取り込み | 購入履歴ページ・スクショ・URL・テキストから商品を抽出し、商品ページを解析・分類・タグ付けして下書きにする | Gemini マルチモーダル、構造化出力、URL Context |
| 🛡️ プライバシーガード | 公開前に、健康・金融・ギフト・個人情報・成人向けなど「見られたくないかも」を検出し、公開範囲を提案する | Gemini Flash-Lite 構造化出力 |
| ✍️ プロフィール | 棚を探索するツールで嗜好を推論し、自己紹介文を下書きする | Agent Development Kit |
| 🤝 相性マッチング | 嗜好の近い人を推薦し、2人の棚を比べて相性・おすすめ・話しかけ例を出す | gemini-embedding-001、Firestore ベクトル検索、ADK |
| 💬 AI分身チャット | フォローした人の「公開棚だけを知る分身」に、おすすめを聞ける | ADK |
| 👀 ウォッチャー | 毎朝自律的に巡回し、ほしい物の値下がりと新作を通知する | ADK、Google 検索グラウンディング、Cloud Scheduler |

### 📥 取り込みエージェント：ログイン情報を預からずに一括取り込み

購入履歴ページはログインしないと見られないので、サーバーからは取得できません。かといって、ショップのパスワードを預かるのは論外です。

そこで **ユーザー自身のブラウザ上で動くブックマークレット** にしました。購入履歴ページでブックマークを押すと、ページ上のリンクとテキストだけを読み取り、`postMessage` で推し棚のウィンドウに渡します。
サーバー側では、商品ページらしいリンク（`/dp/ASIN`、`cid=`、`product_id/RJ...` など）だけを抽出し、商品ページを取得して、タイトル・画像・価格を補完します。

リンクがうまく取れないページでは、ページのテキストやスクリーンショットから Gemini が商品名を抽出します。このとき「注文番号・お届け先・氏名などは抽出しない」「商品名に含まれる宛名は取り除く」ように指示しています。

### 🛡️ プライバシーガード：AIが先に気づき、人が決める

取り込んだ商品は **必ず下書き** になり、プライバシーガードが1件ずつ判定します。

![プライバシーガードが要確認とした商品](/images/oshishelf/04-privacy-guard.png)

実際に、妊娠検査薬・借金返済の本・贈り先の名前が入ったギフトを含む購入履歴を貼り付けると、この3件だけが「要確認」になりました。要確認の商品は **チェックが外れた状態** で表示されるので、うっかり公開してしまうことがありません。

成人向けショップ（FANZA、DLsite の成人向けフロアなど）の作品は、**タイトルを AI に送らずに** ルールで判定します。

### 成人向け作品は「見る側」が選ぶ

成人向け作品も、持ち主は全体公開できます。そのかわり、**見るかどうかの主導権は閲覧する側にあります**。初期状態では他の人の成人向け作品は一切表示されず、18歳以上と申告して表示をONにした人だけが見られます。OFFのままなら、フォローした人の棚でも成人向けでない作品だけを安心して眺められます。この判定はフィード・棚・購入リンクのすべてでサーバー側が行います。

AI 機能も同じ考え方です。持ち主が「自分の成人向け作品を AI に使う」を ON にした場合に限り、成人向け作品の **ジャンルとタグだけ**（タイトル・画像は渡さない）を AI に読ませ、それを反映した自己紹介文（A 版）を作ります。表示 ON の閲覧者には A 版、OFF の閲覧者には成人向け作品を含まない B 版を見せます。相性分析と AI 分身も、持ち主の許可と閲覧者の表示設定がそろったときだけ成人向け作品を考慮します。生成AIの利用ポリシーに沿って、出力は「大人向けではしっとりした恋愛ドラマ系も好み」のような非露骨な表現に限定しています。

### ✍️ プロフィールエージェント：棚を「調べて」から書く

自己紹介文は、棚のデータを丸ごとプロンプトに入れて書かせるのではなく、**ADK のエージェントがツールで棚を探索してから** 書きます。

- `get_shelf_overview`: カテゴリ・ショップ・タグの傾向
- `get_items_by_category`: カテゴリ別の作品
- `search_shelf`: キーワード検索

エージェントは全体の傾向を見て、気になるジャンルを掘り下げてから書きます。どのツールをどんな引数で呼んだかは、画面に「エージェントの行動ログ」として表示されます。生成した文章は下書きで、本人が編集・承認してからプロフィールに載ります。

### 🤝 相性マッチングと 💬 AI分身チャット

棚の作品とタグを `gemini-embedding-001` でベクトル化し、**Firestore のベクトル検索** で嗜好の近い人を推薦します。
プロフィールページでは、相性マッチングエージェントが2人の棚を比較し、相性スコア・共通点・「相手の棚からあなたへのおすすめ」・話しかけ例を出します。

![相性分析とAI分身チャット](/images/oshishelf/03-profile-compat-twin.png)

AI分身は、相手の **全体公開の棚だけ** を知っているエージェントです。「初心者におすすめの1冊は？」と聞くと、棚から作品を選んで答え、その作品は購入リンクになります。棚にない作品を持っているふりはさせず、AIであることも明示しています。

### 👀 ウォッチャー：毎朝、自律的に巡回する

Cloud Scheduler が毎朝 8:00 にウォッチャーを起動します。ウォッチャーは次の手順を自分で組み立てて実行します。

1. ♡を付けた商品の現在価格を確認する
2. 好きなジャンルや作家について、Google 検索グラウンディングで新作を調べる
3. 最近の通知と重複しないかを確認し、ユーザーに通知する

![ウォッチャーの巡回結果と行動ログ](/images/oshishelf/05-watcher.png)

## エージェントに「任せられる」ための設計

開発中、ウォッチャーが **実際には値下がりしていない商品を「値下がりしました」と通知する** ことがありました。監査ログを見ると、前回も今回も同じ価格でした。値下がりかどうかの判断を LLM に任せていたのが原因です。

ここから、**判断は AI に、事実の検証はコードに** という方針を全エージェントに徹底しました。

- **値下がりはコードが判定する**: `check_price` ツールが前回価格と比較して `priceDropped` を返し、検証済みの商品だけを記録します。`notify_user` は、検証済みでない商品の値下がり通知をエラーで拒否します。通知文の価格（¥2,000 → ¥700 など）もコードが付け足します。
- **要約もコードが作る**: 巡回結果の要約は、モデルの自己申告ではなく、ツールの実行回数から作ります（モデルは上限で拒否された通知まで「送った」と書くことがありました）。
- **行動に上限を設ける**: 1回の巡回で検索2回まで、値下がり通知3件・新作通知2件まで。予算を分けることで、新作の通知が値下がりの通知を押し出さないようにしています。
- **ID は実在チェックする**: 相性分析や分身チャットでモデルが返した作品 ID は、棚に実在するかを確認してから使います。
- **人が最後に決める**: 取り込みは下書きから、自己紹介は承認制。AI が勝手に公開することはありません。
- **AI に渡すデータを絞る**: 自己紹介・分身・マッチングに使うのは、全体公開かつ成人向けでない作品だけです。フォロワー限定の作品が AI の出力経由で漏れることはありません。
- **すべてを記録する**: ウォッチャーの実行は、ツール呼び出しの履歴ごと Firestore の `agentRuns` に保存しています。

## アーキテクチャ

![システムアーキテクチャ](/images/oshishelf/architecture.png)

| 役割 | 使用技術 |
|---|---|
| 実行環境 | Cloud Run（Next.js 16 App Router / Server Actions） |
| AIエージェント | Agent Development Kit（`@google/adk`、TypeScript） |
| LLM | Vertex AI Gemini 2.5 Flash / Flash-Lite（サービスアカウント認証、APIキー不要） |
| 埋め込み・検索 | gemini-embedding-001 + Firestore ベクトル検索 |
| グラウンディング | Google 検索（新作調査）、URL Context（商品ページの読み取り） |
| データ | Firestore（クライアントからの直接アクセスはルールで全面拒否） |
| 認証 | Firebase Authentication（Google / メール確認つきメール）→ httpOnly セッション Cookie |
| 定期実行 | Cloud Scheduler（OIDC トークンを audience とサービスアカウントで検証） |

### 実装の工夫

**ツール利用と構造化出力の両立**
Gemini は Function Calling と JSON スキーマ指定を同時には使えません。そこで、エージェントにはツールで自由に調べさせ、最終回答が JSON として解釈できなければ、ツールの実行結果を添えてスキーマ制約つきの整形呼び出しで整える「フォールバック」を用意しました。判断はエージェント、整形は別の呼び出しという分担です。

**安全な商品ページ取得（SSRF 対策）**
ユーザーが入力した URL を取得するので、http(s) のみ許可し、DNS 解決後のプライベート IP やメタデータサーバーを拒否します。リダイレクトは1ホップごとに再検証し、サイズと時間も制限しています。Steam のように価格をページに載せないショップは公式 API から取得し、それでも取れない場合は Gemini の URL Context で読み取ります。

**コストと乱用への備え**
分類やプライバシーチェックのような大量・単純な処理は Flash-Lite、ツールを何度も呼ぶエージェントは Flash と使い分けています。機能ごとにユーザー単位の1日あたり利用上限を設け、Vertex AI の 429 は指数バックオフで再試行します。Cloud Run は最小インスタンス0、プロジェクトには予算アラートを設定しています。

## 今後の展望

- 主要ショップの購入履歴ページ構造に合わせた取り込み精度の向上
- 新作通知の精度向上（発売日の検証、作家・シリーズ単位のフォロー）
- 「この棚から買われた数」をもとにした、作品の口コミ・ランキング
- アフィリエイト収益の一部を棚の持ち主に還元する仕組み

## おわりに

購入履歴は、本人にとっては「好き」の記録そのものです。推し棚は、その記録を安心して公開でき、同じ「好き」を持つ人とつながれる場所を目指しました。
エージェントには取り込みや巡回のような面倒な作業を任せつつ、**公開するかどうかは必ず人が決める** こと、**事実の確認はコードで行う** ことを大切にしています。
